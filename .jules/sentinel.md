## 2025-02-23 - Prevent SQLite LIKE Wildcard and Escape Character Injection
**Vulnerability:** SQL `LIKE` wildcard character injections in the backend service `context.ts` and `logs.ts`. The endpoints explicitly allowed unfiltered `req.query` injection without wildcard protection. In `context.ts`, the developer attempted to escape `%` and `_`, but failed to escape `\`, allowing an attacker to inject an unescaped literal `\%` to bypass the mitigation. In `logs.ts`, wildcard injection allowed for unbound prefix/suffix matching, possibly causing full-table scans. Additionally, Express `req.query` inputs are incorrectly implicitly coerced. Passing an Array or undefined `?search=a&search=b` can crash naive string operations or interpolate into unexpected bounds.
**Learning:** SQLite's `ESCAPE` clause evaluates its expression as a single character. When defining template strings in JS/TS `\\` is compiled to `\`. Thus `ESCAPE '\\'` requires that the actual SQL argument includes `\` for escapes. We must strictly `replace(/[%_\\]/g, '\\$&')` to replace `%` with `\%`, `_` with `\_`, and `\` with `\\`.
**Prevention:** Always escape `%`, `_`, and `\` inputs destined for `LIKE` clauses, and explicitly assert standard input typing via `typeof input === 'string'` in Express.js controller files to avoid Array/Object prototype string coercions and HTTP Parameter Pollution vulnerabilities.
