## 2025-06-01 - Prevent Array Casting in HTTP Query Parameters Causing SQLite DoS
**Vulnerability:** Express `req.query` automatically parses inputs like `?event_type=a&event_type=b` into arrays. Passing these unvalidated arrays directly into `better-sqlite3` execution functions (like `.all(...params)` or `.get(...)`) implicitly unpacks them as bind parameters, or if inside template literals, stringifies them. In `apps/server/src/routes/logs.ts`, passing multiple query parameters leads to "Too many parameter values were provided" error which crashes the endpoint, resulting in a Denial of Service (DoS).
**Learning:** `req.query as Record<string, string>` type assertions in TypeScript do not enforce that incoming Express query parameters are actually strings. They can still be arrays at runtime.
**Prevention:** Always strictly type-check Express query parameters (e.g. `typeof param === 'string'`) before trusting them in string concatenations or database parameter arrays.
