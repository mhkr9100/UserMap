## 2026-05-28 - HTTP Parameter Pollution & better-sqlite3 Array Vulnerability
**Vulnerability:** Unvalidated `req.query` values passed to `better-sqlite3` queries and string methods (`.trim()`). Express parses `?a=1&a=2` as an array, causing server crashes (e.g., `q.trim is not a function`) or database errors (`Too many parameter values were provided`) when arrays are passed to SQLite bindings or mapped into strings via template literals.
**Learning:** Express.js query parameters can be arrays or objects unless strictly parsed. `better-sqlite3` aggressively unpacks array bindings into multiple query parameters. Blindly passing `req.query` objects without type checking or coercion exposes the application to DoS attacks and DB runtime exceptions.
**Prevention:** Always validate and coerce `req.query` values to strings (e.g., `const safeValue = typeof req.query.val === 'string' ? req.query.val : undefined;`) before using them in string methods or SQL queries.
